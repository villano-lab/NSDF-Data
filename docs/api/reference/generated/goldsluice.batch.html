goldsluice.batch¶

Batch mode: run the processing of a dataset definition (goldpan.dataset) over all its raw files.

python -m goldsluice run r76.dataset.toml # process every raw file that is new or changed python -m goldsluice check r76.dataset.toml # read the definition and list what would be done

or from Python, goldsluice.batch.run("r76.dataset.toml"). For every raw file the pulses are read in pieces by the source’s adapter (goldpan.adapters), every step is applied to the channels it names with the Rust kernels, and the quantities (one record per channel, keyed by series, dump and event, without the pulses) are written into the output dataset of the definition, a goldpan Parquet dataset that goldpan.dataset.Dataset.processed() reads (or, with output_format = "root", RQ-style ROOT files under our names, written by goldpan.adapters.rq_root.write and read with rq_root.read; needs goldsluice[root]). A ledger, _goldsluice.json in the output folder, records for each raw file what was done, with what, and how long it took, so that a second run only does what changed: a file is skipped only if its fingerprint (the definition), its stamp (the raw file) and the versions of goldsluice and goldpan that made the output are unchanged (force=True redoes everything). Every output file also carries its provenance in its metadata (goldsluice key).

goldpan does the reading and the definition, so batch mode needs it (pip install goldsluice[batch]).

Processed data must not end up in a Git repository: check and run refuse an output folder that lies inside a Git working tree and whose data files that tree does not ignore (check_output_location; allow_output_in_repo=True, or --allow-output-in-repo on the command line, overrides it).

goldsluice.batch.check_output_location(out, output_format='parquet')[source]¶

Raise ValueError if the output folder out is inside a Git working tree that does not ignore the data files written there (_probe.parquet, or _probe.root for ROOT output): results must not be committed by accident. An output outside any repository, or inside one that ignores it (the processed/ rule of this repository’s .gitignore), passes. When Git cannot answer (it is not installed, or it fails on that folder) nothing is refused.
