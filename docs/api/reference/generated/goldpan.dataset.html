goldpan.dataset¶

A dataset definition: which raw files, how to read them, and which processing to run on them. One TOML file, read by both packages: goldsluice runs the processing in batch, goldpan reads the pulses and the processed quantities back.

The file (r76.dataset.toml):

[dataset]
name = "r76-nai"
output = "~/goldsluice-output/r76-nai"  # the processed quantities: a goldpan Parquet dataset (directory), keep it outside the repository
# output_format = "root"                # optional: RQ-style ROOT files instead, with our names (needs root_detector = N too)
# registry = ["../registry"]            # optional: folders of detector records (goldpan.registry), relative to this file

[[sources]]                             # where the pulses come from; as many as you like
name = "side2"
format = "idx"                          # any adapter: idx, midas, parquet, or one you registered
paths = ["~/idx/07221203_2025_F0001"]   # raw files or dump folders ...
glob = "~/idx/07221203_2025_F*"         # ... and/or a pattern (sorted)
detector = "NAI-S2"                     # the detector name (the adapter's detector_name)
readout = "DCRC_RUN76"                  # a preset of goldpan.config, or { pretrigger_samples = 1000, glitch_samples = 10, sample_period_s = 0.8e-6 }
[sources.read]                          # the other keyword arguments of the adapter's read(), verbatim
channels = { Side2pA = [0, 0], Side2pB = [0, 1] }
roles = { Side2pA = "phonon", Side2pB = "phonon" }

[[processing]]                          # the steps, in order; each adds quantities to the channels it names
algorithm = "peak"                      # a goldsluice algorithm
channels = "role:phonon"                # "all", "role:<role>", or a list of channel names
[processing.params]
glitch_samples = "@readout.glitch_samples"        # "@readout.<field>": taken from the readout of the data
pretrigger_samples = "@readout.pretrigger_samples"
amps_per_adc = 1.5e-9

Nothing is assumed: the readout, the channels and every algorithm parameter are written down, in the file or in a registry it names. With registry (and/or the environment variable GOLDPAN_REGISTRY), a source whose detector is a name in the registry takes the readout, the [sources.read] defaults of its file format and, for ROOT output, root_detector from the detector’s record (goldpan.registry); whatever the file itself states wins, key by key, and a readout that disagrees with the registry’s is a warning. A detector name that is not in any registry is only a label, as before. Dataset.open(path) gives the same file to both packages:

ds = Dataset.open("r76.dataset.toml")
ev = ds.read()                          # the pulses, with the processed quantities attached (one Events)
q = ds.processed()                      # only the processed quantities, no pulses: small and fast
ev.quantities["Side2pA"]["current_max"]

With output_format = "root" the quantities are written as ROOT files in the layout of the collaboration’s RQ files (rqDir/eventTree and rqDir/zip<N>, see goldpan.adapters.rq_root.write), under our names (Side2pA_adc_max); root_detector is that N. Read them with goldpan.adapters.rq_root.read: Dataset.processed() reads the Parquet output only.

The processed quantities are stored one record per channel (quantities["Side2pA"]["adc_max"]), keyed by series, dump, event. python -m goldsluice run <file> produces them; reading them before that raises an error that says so.
