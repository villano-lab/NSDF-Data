python/ library structure: modules, function tables, and status markers

Note 1a · Author(s): Anthony Villano · 22 Sept 2026 (inventory as of 25 Sept 2026) · Status: In progress

This is the reference for how the shared pulse library is organized, placed early because every later note uses it. The history of how it came about and how it was validated is in Note 4.

Code Repository

  • python/ — the library and its tests. Pinned to 61c374f.
  • python/README.md — the conventions in short form. Pinned to 894ef9d.

Why a shared library

Several notebooks had each grown their own copy of the same handful of computations (pretrigger mean and standard deviation, the excursion ratio, baseline subtraction, an FFT power spectrum) with the same constants hardcoded separately in each. That logic now lives in one place, and the notebooks import it.

Framework

  • Samples on the last axis. Every function takes an array shaped (..., n_samples): one pulse (n_samples,) or a batch (n_pulses, n_samples) both work, because every reduction runs along axis=-1. A plain NumPy array is the pulse; there is no custom class. This is what gives uniform inputs across all the categories below.
  • One shared config. A frozen dataclass PulseConfig is passed explicitly to every function, replacing constants copied between notebooks.
  • Three categories, one contract each (table below): quantities are the primitives, cuts are built by thresholding a quantity, operations are independent transforms.
  • Flat modules, no package. Imported by inserting python/ into sys.path, the same convention as nrFanoII_paper2022’s python/ba_bknd_lines.py.

Module contracts

ModuleSignatureReturns
pulse_quantities.py(pulses, config, **params)one number (or spectrum) per pulse, shape (...,) or (..., n_freq)
pulse_cuts.py(pulses, config, **params)one bool per pulse, shape (...,) (True = keep)

pulse_status.py—the status decorator and list_statuses(module), described next

Typical use

import sys
sys.path.insert(0, "/path/to/NSDF-Data/python")
import pulse_io as pio, pulse_cuts as pc
import pulse_operations as op, pulse_quantities as pq
from pulse_config import PulseConfig

config = PulseConfig(pretrigger_samples=500, glitch_samples=10, sample_period_s=1.6e-6)
ids, pulses = pio.load_channel_batch(cdms, pio.filter_by_detector(cdms.get_detector_ids(), 0), 0)

mask = pc.excursion_band_AI(pulses, config)     # under development: emits a UserWarning
power = pq.power_spectrum(op.baseline_subtract(pulses[mask], config), config)

Marking functions done or under development

Every function in the four function modules and the archive module is tagged @status(DONE) or @status(UNDER_DEVELOPMENT, note=...). A done function is called normally. An under-development function still runs, but emits a UserWarning carrying its note on every call, so a notebook that depends on one says so in its own output instead of looking as settled as everything else. list_statuses(module) returns the inventory as {name: (status, note)}; the tables on this page are generated from it.

What is still under development, and why

FunctionModuleWhat is not yet settled
excursion_band_AIpulse_cuts.pyexcursion_band plus the looks_like_pulse veto; both are judgment calls. Check what it removes before trusting it on a new dataset.
excursion_below_percentilepulse_cuts.pyMatches the original “good noise” cut, which is biased toward contaminated-baseline traces when used alone; combine it with quiet_baseline.
looks_like_pulsepulse_cuts.pyA judgment call, not a validated physical criterion. The default min_duration = 50 was picked by eye from a gap in one dataset (179 traces at ≤ 25 samples, 13 at ≥ 168, none between).
excursion_durationpulse_quantities.pyDevised for the pulse veto and checked on one dataset only. Deliberately uses the longest contiguous run: a plain count of samples above half-maximum flagged every trace in the tightened cut.
half_max_time_uspulse_quantities.pyBuilt on rise_sample, so it inherits its status. Only meaningful for a trace that contains a pulse; first used in Note 2a.
rise_samplepulse_quantities.pyHalf-maximum crossing heuristic, used in one exploratory analysis (Cut A rise time, Note 2). Not yet checked against noisy or multi-peak traces.
