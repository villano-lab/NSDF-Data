goldpan.algorithms¶

Trace algorithms: filters and per-trace quantities (ported from pulsedata.algorithms of scdms-analysis-tools).

Like the rest of the package they work on arrays shaped (..., n_samples) and take the readout as a config; the baseline is the pretrigger window of that config (the collaboration version used a fixed 10 ms, which is the window of the Z7 preset). Units follow the trace (amps for Z7 traces) and seconds:

clean = lowpass(pulses, 50e3, config)                      # a filtered copy
peak = pulse_max(pulses, config)                           # one number per trace
ev2 = compute(ev, {"max": pulse_max, "tmax": max_time}, channels=["A"])      # as quantities of an Events

A quantity is any function f(pulses, config) returning one number per trace; compute adds the results to an Events as one record per channel (ev2.quantities["A"]["max"]). The baseline mean, std and subtraction already exist as quantities.pretrigger_mean, quantities.pretrigger_std and operations.baseline_subtract.

goldpan.algorithms.lowpass(pulses, cutoff_hz, config, order=4)[source]¶

Zero-phase Butterworth low-pass filter of every pulse: no shift in time.

The same magnitude response as scipy.signal.sosfiltfilt (1 / (1 + (f / cutoff) ** (2 * order))), applied with the FFT after odd extension of both ends so that the edges do not ring; numpy only. It agrees with scipy away from the edges (see the test).

Parameters:

  • cutoff_hz (float)

  • config (PulseConfig)

  • order (int)
